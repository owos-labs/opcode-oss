# 预设 实现文档

本文档记叙一个预设实现。
预设包含角色预设和物品预设。
所有预设从一个静态且客户端不可见的json文件中读取，并在服务器启动时被map到一系列UI:

GET /items, params: kwd, category
GET /character, 暂时不实现

# 物品预设
当前我们只需要实现物品预设。
其为一个物品dto，其被以如下规则分类：

```json
{
    "version": number,
    "updated_at": timestamp,
    "items": {
        "items": {
            "uuid": { // This in final version will be each entry in a supabase table, but use static impl for now
                "created_by": uuid,
                "created_at": uuid,
                "data": object
            } // mapped item dto
        }
    },
    "melee": { // melee weapon list, uuid item map
    },
    "ranged": {

    }, // etc.
    "attachments": {

    }
}
```

你只需搭建脚手架并在本地文件附加空内容DTO和相应的UI。
这些UI将被放在http://localhost:3000/character-sheet/:id/inventory 的新右侧侧边栏内。
该侧边栏可被收纳，并使用树形结构渲染，可通过接口在点击时拉取每个大类的内容。
点击每个entry可以提供"添加至物品"并添加一个当前版本的数据拷贝对象到loose item，其无需实现任何同步相关内容，并在添加时可查看详情。也可通过拖动加入每个entry内。
你可参考https://github.com/owos-labs/Opcode-D10 来获得一系列物品的预期类型列表。
你无需添加每个新物品，但为每个类别的物品添加一个全量的占位符dto.
按理说暂时只有这些。
