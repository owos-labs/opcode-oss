# Opcode 角色编辑器移植和战斗轮实现文档

# 简述
本项目包含三部分。一个角色卡编辑器和一个多人战斗轮工具，和一个gitbook类内容。
当前我们不实现gitbook类内容。
本项目的服务端并不需要保存任何内容，所有角色卡保存在用户端的IndexedDB，并且所有多人功能使用一个不保存任何记录的纯线上websocket服务来实现。

## UI & UX
我们应该使用apple design skill和一份经过考虑的Occurrence UI Skill：因为本项目并非主站，我们允许更加大胆的动画，和更加先进的设计系统和素材概念。

# Opcode 角色编辑器
此编辑器是一个全量数据的角色编辑器。
该数据包含提供的两个json内的全部内容。
你可以参考这些内容进行移植。
该移植任务目标来自 D:\awesome-project\occurrence-front\apps\app\app\components\characterSheet。
注意：你应该根据已有的布局并重构新布局，而非直接复制源地址的布局到本项目内。
该路由应该被放置在 /character-sheet/ 下。
所有角色卡都应该被保存至OPFS内，并可允许导出和导入为json格式和markdown纯文本格式。
应该允许随编辑的自动保存。这个自动保存应该默认被启动。
所有图片相关的内容应该被存储在本地存储（OPFS）内。

## 角色卡DTO
角色卡DTO包含一个state和一个status。
角色卡包含一个字段，mode，用于控制角色卡在创建模式还是游玩模式。
用户可以变更这个字段，在游玩模式下有些字段不可被更新，在创建模式下有些功能不可被使用。
角色卡可以被复制（duplicate）。
角色卡dto的详细定义被放在本目录下的python dto文件内。

## 路由：基础信息
角色的基础信息包含：角色概念图片[]（存储在IndexDB内），角色名称，昵称，简述，外貌描述。
在这里更新角色的模式（编辑和生涯），这是一个双向操作。只有在生涯模式的角色可以被加入战斗轮。
在生涯模式启用时，需要进行一系列角色合规性检查。

## 路由：属性
此内容同参考目标的属性区块，包含一个主要的技能区域，和一个右侧的属性简报区域。

## 路由：物品
此内容同参考目标的物品区域，但提供更好的用户体验。针对所有物品和武器，我们提供一系列预设，这些预设以一系列模式被保存。该列表在preset.json内。
物品可以被装入容器，容器可在侧边栏内添加并渲染为一个特殊的物品类型，其可以被折叠。
使用拖动将不同物品的顺序重新安排并进行切换。

主导航用于切换战斗轮工具，角色卡编辑器和gitbook类内容。

## 侧边导航：角色卡编辑器
此编辑器侧边导航包含一个角色选中态，一个基础信息选中态，一个物品选中态，一个属性选中态，和一个默认态。
针对默认态，此侧边栏导航渲染所有用户的角色卡，用户可以在首栏进行筛选和新建。

针对选中角色的情况下，侧边栏渲染角色内部导航。
内部导航包含三个导航：基础信息，属性，和物品。

针对物品选中态，其展示该角色的所有物品列表，这个物品列表可以被筛选且可以在这里进行分组和添加/移除物品。
每个分组可以被用户单独添加，删除，和编辑。

针对属性选中态，其渲染和允许编辑角色的基础属性。

针对基础信息选中态，其和角色选中态相同。
